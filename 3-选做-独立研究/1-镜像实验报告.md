# 选做实验①：国内镜像机制验证（flutter config 与环境变量实验）

> 实验日期：2026-09-23 ｜ 环境：Flutter 3.47.2 stable / Windows 11 / PowerShell 5.1

## 一、实验目的

1. 验证 `PUB_HOSTED_URL` / `FLUTTER_STORAGE_BASE_URL` 环境变量对 pub 依赖拉取源的实际控制作用；
2. 实测国内镜像（flutter-io.cn）与官方源（pub.dev）在冷缓存条件下的下载耗时差异；
3. 理解镜像机制的底层原理，形成"什么时候该用镜像"的工程判断。

## 二、实验设计

在临时目录创建一个测试项目并 `flutter pub add dio`，然后以**三组对照、严格串行**的方式执行 `flutter pub get`，每次拉取前**手动删除对应源的 hosted 缓存目录**，保证冷缓存公平对比：

| 组别 | PUB_HOSTED_URL | 缓存处理 | 测量内容 |
|------|----------------|----------|----------|
| Run A | `https://pub.flutter-io.cn`（镜像） | 删除 `hosted\pub.flutter-io.cn` | 冷缓存 `pub get` 耗时 |
| Run B | `https://pub.dev`（官方） | 删除 `hosted\pub.dev` | 冷缓存 `pub get` 耗时 |
| Run C | `https://pub.flutter-io.cn`（镜像） | 删除 `hosted\pub.flutter-io.cn` | 复测镜像，验证波动 |

> 计时用 PowerShell `System.Diagnostics.Stopwatch`，覆盖 `pub get` 全过程（解析依赖 + 下载 + 解压）。

## 三、镜像机制的原理说明

1. **两个环境变量分工不同**：
   - `PUB_HOSTED_URL`：控制 Dart 包（pub.dev 上的依赖）从哪里下载；
   - `FLUTTER_STORAGE_BASE_URL`：控制 Flutter SDK 制品（engine 工具、Gradle wrapper 等）从哪里下载。
2. **工作方式**：Flutter 工具把 pub.dev 域名整体替换为镜像域名，请求的 URL 路径结构不变，属于"镜像站透明替换"。
3. **缓存按域名分目录**：本机 pub 缓存位于 `...\pub-cache\hosted\` 下，`pub.flutter-io.cn` 与 `pub.dev` 各占一个目录、**互不通用**——这正是实验中切换源后必须重新下载的原因，也是三组实验要分别删各自缓存目录的原因。
4. `flutter config` 并不直接管理这两个镜像变量（它管理的是 `--enable-windows-desktop` 等开关与 android-sdk 路径等）；国内镜像在本机的实际生效方式是**用户级环境变量**（`setx` 写入注册表，`flutter doctor -v` 里能看到生效值）。

## 四、实验数据

原始数据见同目录 `exp1_data.txt`（由脚本自动记录）：

| 组别 | 源 | 耗时 | 退出码 |
|------|----|------|--------|
| Run A | 镜像 flutter-io.cn（冷） | **151.5 s** | 0 |
| Run B | 官方 pub.dev（冷） | **13.1 s** | 0 |
| Run C | 镜像 flutter-io.cn（冷，复测） | **276.9 s** | 0 |

## 五、结果分析

1. **官方直连反而最快（13.1s）**：本机当前网络直连 pub.dev 十分顺畅。镜像并不总是"更快"。
2. **镜像速度波动大**：同为镜像冷缓存，Run A 151.5s 与 Run C 276.9s 相差近一倍，说明镜像共享带宽在晚高峰时段不稳定。
3. **镜像的核心价值是"可达性兜底"而非"速度优势"**：当网络环境阻断 pub.dev（部分校园网/企业网/热点）时，镜像是唯一可行路径；网络通畅时直连更快。这解释了为什么指南要求预配置镜像——它是**稳定性保险**，不是加速器。

## 六、实验过程中的意外发现（真实踩坑）

1. **pub 缓存锁是全局互斥的**：第 1、2 版实验让两个 flutter 进程并行跑（一边构建模拟器应用一边做实验），双方都报 `Failed to update packages`，数据全部作废。**教训：任何 pub 操作必须严格串行**，本报告的三组数据是第 3 版（v3）串行重跑的结果。
2. **管道截断会杀死上游进程**：实验脚本调试中曾用 `| Select-Object -First N` 截断长输出，PowerShell 会提前终止管道上游的 flutter 进程。
3. 缓存目录按域名隔离的设计意味着**切换镜像不能复用另一源的缓存**，首次切换必然全量重新下载。

## 七、结论

- 环境变量机制验证成功：改 `PUB_HOSTED_URL` 后下载域名与缓存目录同步切换，`pub get` 均正常完成（三组 exit=0）；
- 本机环境下官方直连 13.1s 显著优于镜像（151.5s / 276.9s）；
- 工程建议：镜像环境变量保持常驻（兜底），不必为"提速"而追求镜像——瓶颈在可达性而不在带宽。
