# 任务3 · 手工安装原理说明（用自己的话解释 SDK、平台工具链、PATH 三层关系）

> 全文为本人理解后的口头化表述（经 AI 对话整理，逐句可解释），配本机真实踩过的例子。

## 一句话总览

**Flutter SDK 是"发动机"，平台工具链是"每条赛道的上路许可和维修厂"，PATH 是"把钥匙插进点火孔"。**
三者齐了，`flutter run` 才能把同一份 Dart 代码送上 Android、Windows、Web 三条赛道。

## 第一层：Flutter SDK（含 Dart SDK）——发动机本体

`C:\Users\lenovo\flutter_dev\flutter\` 里装的是 Flutter 框架源码、`flutter` 命令行工具
和内置的 Dart SDK。它是"跨平台"的部分：负责 Widget、渲染描述、Dart 编译。
`flutter --version` 能打印 `Flutter 3.47.2 / Dart 3.13.2` 两个版本号，
正是因为 SDK 里同时捆绑了框架和语言工具链两样东西。

类比：发动机决定了车能跑，但它自己不知道各地交规，也不认识路。

## 第二层：平台工具链——每个平台的"上路许可 + 维修厂"

Flutter 只负责描述界面和业务逻辑；真正把它变成某个平台能跑的产物，靠的是各平台自己的工具链：

| 目标平台 | 需要的工具链 | 本机情况 |
|----------|--------------|----------|
| Android | Android SDK（编译、打包 APK）+ NDK（native 部分）+ JDK + 模拟器 + 许可协议 | Android Studio 在 D 盘，SDK 在 `%LOCALAPPDATA%\Android\sdk`；本次补装了 NDK 28.2.13676358、system-images；接受了全部许可 |
| Windows 桌面 | Visual Studio 的"使用 C++ 的桌面开发"工作负载（C++ 编译器与 Windows SDK） | 已装 VS 生成工具 2022，doctor `[√]` |
| Web | 仅需浏览器（Chrome/Edge）作为运行载体 | Chrome 137，doctor `[√]` |

**为什么许可协议属于工具链层**：Android SDK 的各组件（构建工具、系统镜像、NDK）
是带法律授权的，不写下"已接受"的许可文件，构建工具拒绝开工——本次问题 1 的
"license status unknown" 卡的就是这一层，而不是第一层 Flutter SDK。

类比：发动机再好，去 Android 赛道要有赛道牌照（许可）、维修厂（NDK/SDK 组件），
去 Windows 赛道另有一套。跨平台框架省的是"造发动机"的功夫，省不掉"每条赛道的上路手续"。

## 第三层：环境变量（PATH 与镜像变量）——钥匙能插进点火孔

- **PATH**：把 `flutter\bin` 加进 PATH 后，任意目录的终端敲 `flutter` 才找得到程序；
  否则报 `flutter: command not found`。**改完 PATH 必须重开终端**——旧终端的环境
  副本不会自动刷新，"命令找不到"九成是这个原因。
- **JAVA_HOME / PATH 中的 Java**：Gradle 与 sdkmanager 是 Java 程序，找错 Java 版本
  会报 `UnsupportedClassVersionError`。本次实操就真实遇到：PATH 里残留了旧 Java 12，
  sdkmanager 启动即报"class file version 61.0 不识别"；把 Android Studio 自带 JBR
  （Java 17+）的 bin 前置到 PATH 后才正常——印证"环境变量决定工具链找谁干活"。
- **镜像变量**：`PUB_HOSTED_URL` 与 `FLUTTER_STORAGE_BASE_URL` 把包与引擎的下载
  从境外源切到国内镜像（flutter-io.cn）。本机预配置后，每条 flutter 命令都会
  提示 "assets will be downloaded from https://storage.flutter-io.cn"，
  这是第三层影响第一层下载行为的直接证据。

类比：钥匙（终端命令）插进点火孔（PATH 找到 exe），车才听你指挥；
镜像变量相当于"把加油站换成家门口的"，加的油一样，但不用排跨国长队。

## 三层关系图（文字版）

```
  你在终端敲 flutter run
        │  ① PATH 帮终端找到 C:\...\flutter\bin\flutter
        ▼
  Flutter SDK（第一层）
   解析命令 → 编译 Dart → 需要目标平台产物
        │  ② 调用对应平台工具链
        ▼
  平台工具链（第二层）
   Android: SDK+NDK+JDK+许可 → APK → 模拟器
   Windows: VS C++ 工作负载 → exe
   Web    : 浏览器加载 JS/WASM
        ▲
        │  ③ 镜像变量 / JAVA_HOME 等环境变量
        │     影响下载来源与工具链调用（第三层贯穿①②）
```

## 用本课踩过的坑反向验证三层缺一不可

1. 只有第一层、第二层许可缺失 → doctor 报 `license status unknown`，构建被拖崩。
2. 第二层 NDK 缺失 → Gradle `Package ndk not found`。
3. 第三层 Java 版本不对 → `UnsupportedClassVersionError`，sdkmanager 起不来。
   三层分别修好后，doctor 全绿、三端可跑——关系闭合。
